# Anonymous-first shortlist, claimed by email, shared by unguessable link

A visitor completes the entire selection journey — browse, filter, interview, shortlist — without an account. The shortlist lives against the session from the first name saved. Only at the end, and only if the visitor wants to keep it, are they asked for an email address and a display name; that claim mints an unguessable token and a read-only page at `/s/{token}` they can send to family. We rejected requiring registration first because the product's value is apparent only after a parent has narrowed thousands of names to a handful, and asking for credentials before that trade is visible is where such funnels lose people. Password accounts from the accounts work remain and are unchanged: claiming by email is a lighter, separate path, not a replacement, and a visitor who already has an account simply keeps using it.

The share link is **read-only in v1**. The domain already models multiple members per shortlist with per-entry attribution, because the eventual product is an expecting couple deciding together — so the token and route are designed to admit a second, editable link type later without reshaping the schema. Anyone holding the link can read the list, so the token must be long and random rather than a sequential id, and the page must carry `noindex` — a shortlist tied to a named person and an email address is personal data, and an indexed one would be a leak. Storing the email brings the claim under the same consent, privacy-policy and deletion obligations as a registered account, and the deletion path must work from the link alone, since a claimer has no password with which to log in and ask.
